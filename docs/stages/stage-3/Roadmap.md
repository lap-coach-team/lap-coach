# Project Roadmap: Цифровий тренер для автоспорту

## Фаза 1: Дослідження, архітектура та підготовка інфраструктури

Ця фаза фокусується на валідації технологій та підготовці фундаменту вебзастосунку для паралельної роботи п'яти розробників.

| № | Назва роботи | Опис та цілі |
| --- | --- | --- |
| 1 | Юридичний аудит карт | Аналіз умов використання супутникових знімків Esri для легального інтегрування у власний продукт. |
| 2 | Проєктування архітектури | Створення архітектури вебзастосунку з локальною обробкою: телеметрія витягується у браузері, відео не вивантажується на сервер (збереження лише кількох МБ метаданих). |
| 3 | UI/UX дизайн | Адаптація наявного HTML-макета демо-версії розбору заїзду у повноцінні дизайн-макети інтерфейсу. |
| 4 | Налаштування CI/CD | Створення репозиторіїв, налаштування середовищ розробки, тестування та продакшену для команди. |
| 5 | Технічна валідація GPMF | Перевірка бібліотеки gopro-telemetry для стабільного витягування GPS-координат, швидкості та перевантаження з відеофайлів GoPro HERO5–HERO11 та HERO13. |

## Фаза 2: Обробка даних та базові алгоритми (Ядро)

Реалізація ключової бізнес-логіки бекенду та алгоритмів роботи з GPS-даними.

| № | Назва роботи | Опис та цілі |
| --- | --- | --- |
| **6** | Модуль парсингу відео | Розробка фронтенд-модуля для завантаження файлів GoPro та парсингу GPS-даних (~18 Гц) безпосередньо на клієнті. |
| **7** | Алгоритм поділу на кола | Написання математичної логіки для автоматичного визначення лінії старту/фінішу та розрахунку часу кожного кола. |
| **8** | Фільтрація невалідних кіл | Розробка фільтра, який автоматично відкидає кола з виїздом на піт-лейн або критичними помилками GPS. |
| **9** | Корекція зсуву GPS | Реалізація базового алгоритму вирівнювання зсуву GPS-координат між різними колами однієї сесії. |
| **10** | Серверна інфраструктура | Розробка API та бази даних для збереження користувачів, їхніх сесій та історії найкращого кола по трасі. |

## Фаза 3: Картографія та аналітика заїзду

Фокус на геопросторових даних та алгоритмах пошуку втрат часу. Межі MVP обмежені однією відкритою трасою.

| № | Назва роботи | Опис та цілі |
| --- | --- | --- |
| **11** | Оцифрування траси MVP | Ручне створення цифрової карти картодрому «Жага швидкості»: обведення меж за супутниковими знімками та фото з дрона. |
| **12** | Рендеринг траєкторії | Розробка візуального модуля для накладання GPS-траєкторії пілота на реальні межі траси (невпевнені ділянки відображатимуться пунктиром). |
| **13** | Ідентифікація поворотів | Створення алгоритму, що автоматично знаходить повороти, точки гальмування, апекси та розраховує швидкість на виході. |
| **14** | Механізм порівняння кіл | Реалізація логіки порівняння телеметрії кожного пройденого кола з найкращим колом сесії. |
| **15** | Сортування втрат часу | Розробка функції аналізу, яка сортує всі повороти за кількістю втраченого часу (найбільші втрати перші). |

## Фаза 4: Рушій порад та інтерфейс користувача

Перетворення сухих математичних даних на зрозумілий для новачків продукт.

| № | Назва роботи | Опис та цілі |
| --- | --- | --- |
| **16** | Рушій текстових порад | Створення генератора 2–3 конкретних висновків простою мовою з підставленням цифр (наприклад, різниця в метрах при гальмуванні) без телеметричного жаргону. |
| **17** | Синхронізація з відео | Розробка плеєра, який дозволяє відтворювати фрагмент завантаженого відео точно в момент проходження проблемного повороту. |
| **18** | Генератор плану тренувань | Реалізація модуля, який формує план на наступний заїзд: на яких 1–2 поворотах зосередитися та що саме змінити. |
| **19** | Верстка дашборда | Інтеграція таблиці часу, карти, блоків порад та графіків у єдиний інтерфейс користувача. |
| **20** | Система оцінювання порад | Додавання кнопок збору зворотного зв'язку до кожної поради для вимірювання корисності. |

## Фаза 5: Тестування, MVP-реліз та аналітика

Завершальний етап для стабілізації продукту та перевірки бізнес-гіпотез.

| № | Назва роботи | Опис та цілі |
| --- | --- | --- |
| **21** | Точнісне тестування | Внутрішнє QA-тестування алгоритмів: перевірка, чи середня похибка вимірювання часу кола не перевищує цільові 0,05 с. |
| **22** | Закрите бета-тестування | Запуск застосунку для реальних пілотів прокатного картингу на трасі «Жага швидкості». |
| **23** | Налаштування продуктової аналітики | Інтеграція трекінгу подій для відстеження North Star метрики: «Кількість розборів за тиждень, де пілот оцінив хоча б одну пораду як корисну». |
| **24** | Валідація бізнес-моделі | Розробка та інтеграція анкети для бета-тестерів щодо готовності платити за тарифи Pro ($3 / $5 / $8). |
| **25** | Підготовка до масштабування | Аналіз зворотного зв'язку, багфікс та планування архітектури для інтеграції треків з мобільних телефонів (наступний етап після MVP). |
